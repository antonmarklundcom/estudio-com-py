## Decisions

- Did not cap the home Guías list at 6: `.guide-list`/`.guide-row` is an unconstrained flex
  column (no max-height, no grid), so 8 rows render as a normal longer list, not an overflow —
  checked at 375×812. No restyle, no code change.
- Left `content/nav.php` untouched: it already carries an unused `guias` array for the footer,
  but rendering it requires a new footer column in `partials/footer.php`, which is outside this
  phase's owned paths ("add nothing... without a CSS change"). Noted in `KNOWN-ISSUES.md`
  rather than touched.
- Found during verification, not fixed (hard limit, `templates/**` frozen): `templates/segment.php`
  never reads `$record['guides']`, even though `content/areas-ciudades.php` already forwards
  `'guides' => $svc['guides']` into every área × ciudad record. So the 56 combo pages carry the
  guide slug in their data but never render a "Guía relacionada" band — confirmed on
  `/ciudades/luque/familia/`. This is a genuine gap against the phase prompt's exit wording ("a
  sampled combo page show[s] the band"); per the prompt's own hard-limit instruction ("if a
  cross-link needs a template change, write it to KNOWN-ISSUES.md ... don't do it"), it is
  documented there instead of touched.
- Gate-3 audit (re-run `verify.sh` on merged main + adversarial re-read of the merged diff)
  found no defect: all 8 `guides` mappings match their área's `relatedService`, no invented
  facts, no unauthorized phrasing. This commit is therefore log + plan.md §9 only — no code
  change.
