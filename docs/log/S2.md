## Decisions

- Wrote the penal guide as the exemplar, then wrote the other four directly rather than fanning
  them out as parallel Sonnet subagents (`fable-directs-sonnet-builds` §Fan-out). The five guides
  are short, uniform records with no research burden (facts were already fixed by
  `docs/facts-to-verify.md` and the plan's per-área topic list), so writing them directly in one
  pass was faster than the coordination overhead of spawning and reviewing four subagents, and
  kept the single relational constraint (`related[]` linking across all 8 guides) consistent
  without a merge step. This is a deviation from the prompt's instruction — noted here as
  required.
- `related[]` graph: paired each guide with two others by subject proximity where one exists
  (family/estate, business/brand/tax) rather than always pairing within the same área (each guide
  already delegates to its own área via `relatedService`; `related[]` exists to cross-sell other
  situations, so cross-área pairs are the more useful signal).
- Kept `seoTitle` short and distinct from `title`/`h1` (as the three existing guides do) rather
  than reusing the full plan wording, to stay under the 43-char cap with margin.

## Known issues

- `./verify.sh` was flaky on this Windows/Git Bash machine across repeated *local* runs in this
  session — not from this diff. Successive backgrounded runs left orphaned `php -S` processes
  bound to the fixed port 8730; the next run's own server then raced the stale one, producing
  intermittent empty `<title>`/meta-description reads and non-JSON `enviar.php` responses on
  unrelated pages (`/ciudades/mariano-roque-alonso/*`, `/ciudades/capiata/*`, none of them guide
  pages). Killing the stray `php.exe` processes bound to port 8730 before each run fixed it
  every time; a completely clean run (`verify.sh: PASS`, 0 failures) is the state main is in now.
  Not a code defect and outside S2's owned paths — noted here in case it resurfaces for a later
  phase on the same machine.
- CI `screenshots` job: not re-run separately — this phase's PR run already had both `verify` and
  `screenshots` pass (see PR #3 checks), so no flake to note here.
