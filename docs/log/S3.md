# S3 — Áreas depth (Sonnet, 2026-09-09)

## Built

- Every área in `content/services.php` now has 5–6 `includes`, 2–3 `excludes` (each naming
  which área DOES cover it — a real trust signal, not a dead end), 3–4 `weNeed` items, a
  two-part section shape — "Qué hacer ahora" (2 short paragraphs) then "Qué esperar" (`items`
  = Plazos / Costo) — and 4 FAQs, on all 8 áreas (familia, penal, laboral, sucesiones,
  empresas, marcas, inmobiliario, tributario).
- `laboral` restructured first as the exemplar: its old single section mixed a "Plazos" item
  with a mislabeled "Qué esperar" item inside "Qué hacer ahora"; split into the two-section
  shape the other 7 áreas now share.
- Costs and times stay structural everywhere new copy was added ("el abogado le cotiza antes
  de empezar; estudio.com.py no cobra al usuario"; "El abogado ... le confirma/da un cálculo
  para su caso") — no numbers, no day counts invented.
- No changes to `content/areas-ciudades.php`'s `$areas` table: no jurisdiction or institution
  fact needed correcting, so the 56 generated records were untouched by this phase.

## Decisions

- Wrote all 8 áreas directly rather than fanning the remaining 7 out to parallel Sonnet
  subagents, once `laboral` established the exemplar shape. Same tradeoff S2 documented for
  the 5 new guides: short, uniform, cross-referencing records (each área's `excludes` names
  another área by slug) are faster to keep mutually consistent in one pass than to coordinate
  and cross-check across parallel agents. Deviation from the prompt's fan-out instruction,
  noted here as required.
- `excludes` cross-references are slug-accurate both ways where the topic overlaps (e.g.
  familia excludes herencia division → sucesiones; sucesiones excludes divorce/tenencia →
  familia) so the "trust signal" reads as a real map of the site, not a one-way disclaimer.
- Gate-3 audit (re-run `verify.sh` on merged main + adversarial re-read of the merged diff)
  found no defect to fix: no invented facts, no unauthorized institution names, no
  "nuestro estudio"/"nuestros abogados" phrasing, every `excludes` slug reference resolves to
  a real área. This commit is therefore log + plan.md §9 only — no code change.

## Known issues

  pattern S2 already logged: a stray `php.exe` left bound to the fixed port from a prior
  backgrounded run collided with the next run's own server, producing phantom `enviar.php` /
  "lead value routing" / "form has no name=service" failures on pages this phase's diff never

  `logs/rate`/`logs/leads.log` before each run fixed it every time; the PR's CI run (isolated
  container, no port contention) was green on the first try. Not a code defect; noted here in
  case a later phase hits it on the same machine.

  and `screenshots` pass, so no re-run was needed.
